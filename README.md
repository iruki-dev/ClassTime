# ClassTime — 시간표 기반 강의 자동 녹음 앱

시간표를 한 번 등록해 두면 수업 시간에 맞춰 **자동으로 녹음이 시작되고 끝나며**,
파일 이름과 폴더가 **과목별로 자동 정리**됩니다. PC 로는 USB 케이블만 꽂으면 바로 옮길 수 있습니다.

Kotlin + Jetpack Compose + Room 으로 작성된 네이티브 안드로이드 앱입니다.

---

## 1. 이 앱이 해결하는 것

| 기존 (기본 녹음 앱) | ClassTime |
|---|---|
| 수업마다 직접 녹음 버튼을 눌러야 함 | 시간표대로 알아서 시작/정지 |
| `녹음_001.m4a` 같은 이름 | `자료구조_2026-03-04_0930.m4a` |
| 한 폴더에 전부 뒤섞임 | `Music/ClassTime/자료구조/` 처럼 과목별 폴더 |
| 나중에 일일이 이름 바꾸고 분류 | 분류 작업 자체가 없음 |

---

## 2. 주요 기능

### 시간표 (한 과목 = 여러 교시, 교시마다 시간 자유)
- 수업을 추가할 때 **교시를 원하는 만큼 더합니다.** 각 교시는 `요일 + 시작 + 종료` 이고,
  - 요일마다 시간이 달라도 됩니다 (예: 자료구조 월 09:00–10:15, 수 13:30–14:45)
  - 같은 요일에 두 번 열려도 됩니다 (예: 실습 수 10:00–11:00, 수 15:00–17:00)
- 과목명·교수·강의실·색·자동녹음 여부는 과목 전체에 한 번만 지정합니다.
- 같은 과목의 모든 교시는 하나의 그룹(`groupId`)으로 묶여, 수정·삭제가 그룹 전체에 적용됩니다.

### 대기 모드 — 자동 녹음에 소리가 들어가게 하는 핵심

안드로이드는 **녹음 서비스가 포그라운드로 전환되는 그 순간** 앱이 화면에 있었는지로 마이크
접근 권한을 고정합니다(while-in-use). 한 번 잡으면 앱을 닫든 화면을 끄든 유지되고, 못 잡으면
`MediaRecorder` 가 예외 없이 **무음을 그대로 인코딩**합니다.

수업 시간 알람은 당연히 백그라운드에서 울리므로, *알람이 서비스를 새로 띄우는* 구조로는
자동 녹음이 영원히 무음입니다. 실제로 이런 증상이 나옵니다:

| 녹음 시작 순간 앱이… | 결과 |
|---|---|
| 화면에 없음 | 무음 (도중에 앱을 열면 그때부터만 소리가 들어옴) |
| 화면에 있음 | 정상 — 이후 앱을 닫거나 화면을 꺼도 끝까지 녹음됨 |

**대기 모드**는 앱을 열 때 녹음 서비스를 미리 포그라운드로 올려 마이크 권한을 잡아 둡니다.
수업 시간에는 이미 권한을 쥔 그 서비스가 그대로 녹음을 시작하므로 소리가 정상적으로 들어옵니다.

- 기본으로 켜져 있고, 홈 화면 카드에서 상태 확인 및 끄기가 가능합니다.
- 앱을 열 때마다 자동으로 갱신됩니다. 마이크 없이 떠 있던 상태였다면 **앱이 화면에 있는 지금**
  서비스를 내렸다 다시 올려 권한을 새로 잡습니다.
- 대기 중에는 낮은 우선순위 알림이 하나 남습니다(포그라운드 서비스 요건).
- **재부팅 후에는 앱을 한 번 열어 주세요.** 부팅 직후에는 화면에 앱이 없어 권한을 잡을 수
  없습니다. 이 경우 앱이 알림으로 안내합니다.
- 그래도 소리가 안 들어오면 녹음 중 진폭을 감시해 **‘무음이 녹음되고 있습니다’ 알림**을 띄우고,
  목록에도 해당 건을 빨갛게 표시합니다.

### 자동 녹음
- 시간표의 각 수업에 **정확 알람(exact alarm)** 을 겁니다. 수업 시작 시각에 포그라운드 서비스가
  떠서 녹음을 시작하고, 종료 시각에 멈춥니다.
- **녹음 종료를 3중으로 보장합니다:** ① 외부 종료 알람(주 수단) ② 워치독 알람(기기가 절전에
  들어가도 정확히 깨어남) ③ 최대 길이 상한 4시간. 어느 하나가 실패해도 녹음은 끝납니다.
- "재설정"과 "놓친 녹음 따라잡기"를 분리했습니다. 종료 알람은 알람만 다시 걸고 녹음을 시작하지
  않으므로, **끝난 수업이 곧바로 다시 녹음되는 일이 없습니다.**
- **재부팅 · 앱 업데이트 · 시간대 변경** 후에도 `BootReceiver` 가 알람을 복구하고,
  마침 수업 중이면 놓친 녹음을 이어서 시작합니다.
- 과목별로 자동 녹음을 개별적으로 끌 수 있습니다 (수업 편집 → '자동 녹음' 스위치).

### 학기 · 휴강 · 보강 (개강/종강 대비)
시간표 화면 오른쪽 위 달력 아이콘 → **학기 · 휴강 · 보강** 화면:
- **학기 기간**: 개강일·종강일을 지정하면 그 기간에만 자동 녹음 알람이 잡힙니다.
  개강 전에는 아무 것도 녹음하지 않고, 종강일이 지나면 자동 녹음이 멈춥니다(수동은 계속 가능).
- **휴강 / 공휴일**: 특정 날짜에 특정 과목만, 또는 그날 전체를 쉬는 것으로 표시합니다.
  해당 주는 건너뛰고 그 다음 수업일에 자동으로 알람이 잡힙니다.
- **보강**: 시간표에 없는 날짜·시간에 한 번 열리는 수업을 등록합니다. 자동 녹음 여부도 지정할 수
  있고, 원 과목과 연결하면 그 과목 폴더로 저장됩니다.

### 수동 녹음 + 자동 라벨링
- 홈 화면의 큰 버튼으로 즉시 녹음합니다.
- 이때 **현재 시각을 시간표(휴강·보강 반영)와 대조해 과목명을 자동으로 붙입니다.**
  (수업 시작 5분 전 ~ 종료 10분 후까지 그 수업으로 인정)
- 시간표에 없는 시간이면 과목명을 물어보고, 비워두면 `기타` 폴더로 갑니다.

### 파일 관리
- 저장 위치: `내장 저장소 / Music / ClassTime / <과목명> / <과목명>_<날짜>_<시각>.m4a`
- 형식: AAC 96 kbps / 44.1 kHz `.m4a` — 1시간 강의가 약 43 MB
- 앱 안에서 재생(탐색 바 포함), 이름 변경, 삭제, 공유가 됩니다.
- 과목 폴더 전체를 한 번에 공유(드라이브·메일 등)할 수도 있습니다.

### PC 로 옮기기
1. **USB (권장)** — 케이블 연결 → 파일 전송 모드 → `내장 저장소/Music/ClassTime/` 폴더를 통째로 복사.
   앱이 공용 `Music` 폴더에 저장하므로 별도 내보내기가 필요 없습니다.
2. **공유 메뉴** — 녹음 목록에서 `⋮` → '보내기 / PC로 옮기기' → 드라이브·메일 등으로 전송.
   과목 헤더의 공유 아이콘을 쓰면 그 과목 전체를 한꺼번에 보냅니다.

## 3. 빌드 방법

### Android Studio (가장 쉬움)
1. Android Studio 로 이 폴더를 엽니다.
2. Gradle 동기화가 끝나면 Run ▶ 을 누릅니다. `local.properties` 는 자동 생성됩니다.

### 명령줄
JDK 17 과 Android SDK (platform 34, build-tools 34.0.0) 가 필요합니다.

```bash
# SDK 위치 지정 (Android Studio 를 쓰면 자동 생성됨)
echo "sdk.dir=$ANDROID_HOME" > local.properties

./gradlew assembleDebug         # 디버그 APK
./gradlew assembleRelease       # 릴리스 APK (R8 적용)
./gradlew :app:lintDebug        # 정적 분석
./gradlew :app:testDebugUnitTest  # 단위 + Robolectric 테스트 (73개)
```

산출물: `app/build/outputs/apk/debug/app-debug.apk`

기기에 설치: `adb install -r app/build/outputs/apk/debug/app-debug.apk`

> 이 저장소의 코드는 위 네 명령이 모두 통과하는 것을 확인했습니다.
> (디버그 APK ~17.9 MB / 릴리스 ~1.7 MB, Kotlin 경고 0건, lint 오류 0건, 테스트 73개 통과)

## 4. 처음 실행할 때 꼭 해야 할 설정

앱이 홈 화면에서 빨간 카드로 안내하지만, 미리 알아두면 좋습니다.

1. **마이크 권한** — 없으면 녹음 자체가 불가능합니다.
2. **대기 모드 켜 두기** — ⚠️ **자동 녹음 소리는 여기에 달려 있습니다.** 기본으로 켜져 있고,
   앱을 열면 자동으로 준비됩니다. 위 2장 참고.
   (‘다른 앱 위에 표시’는 일부 기기에서만 통하는 보조 수단이라 선택 항목입니다.)
3. **알람 및 리마인더 권한** (Android 12+) — 꺼져 있으면 시스템이 알람을 몇 분씩 미루기 때문에
   수업 앞부분이 잘릴 수 있습니다.
4. **알림 권한** (Android 13+) — 녹음 중 알림이 포그라운드 서비스 유지에 필요하고,
   무음 경고도 이 알림으로 옵니다.
5. **배터리 최적화 제외** — 제조사(삼성·샤오미 등) 절전 기능이 앱을 강제 종료하면
   자동 녹음이 통째로 실패할 수 있습니다.

홈 화면이 위 항목 중 해결되지 않은 것만 카드로 띄우고, 버튼 한 번으로 해당 설정 화면을 엽니다.

### 동작 흐름 (자동 녹음)

```
시간표 / 학기 / 예외 저장, 앱 실행, 부팅
   └→ ScheduleManager.rescheduleAll()   ← 알람만 다시 건다. 녹음은 시작하지 않음
        · 정규 수업: nextValidDate(시작), nextValidDate(종료) 를 각각 계산
          (진행 중인 수업은 '오늘 종료' 알람이 다음 주로 밀리지 않음)
        · 학기 밖 / 휴강 주는 건너뜀,  종강 후에는 알람 없음
        · 보강: 미래 & 학기 안 & 자동녹음 켜진 것만

[앱 실행]    MainActivity.onResume → RecordingService.startStandby(fromForeground=true)
   → 지금 앱이 화면에 있으므로 startForeground() 가 마이크 권한을 함께 잡는다
   → 서비스는 수업 시간까지 이 권한을 쥔 채 대기

[수업 시작]  AlarmReceiver(START) → RecordingService.startAuto / startMakeup
   → 대기 중인 서비스가 그대로 받는다 (startForeground 재호출 없음 = 권한 유지)
   → 과목/보강 조회 → Music/ClassTime/<과목>/ 파일 생성 → MediaRecorder 시작
   → DB '녹음 중' 행 + 알림 → 워치독 예약(수업 종료 시각 / 최대 4h)
   → rescheduleAll (다음 회차만 재예약, 따라잡기 안 함)

[수업 종료]  AlarmReceiver(STOP) → RecordingService.stop()   ← 주 수단
   또는       RecordingWatchdogReceiver 알람 발동               ← 종료 알람이 실패했을 때
   또는       4시간 상한                                        ← 최후
   → finalizeAndStop(): 앱 스코프 + NonCancellable 에서
      MediaRecorder 정지 → IS_PENDING 해제 → DB 행 ongoing=false + 길이·용량
   → (서비스가 중간에 죽어도 이 마무리는 끝까지 진행됨)
   → updateStatus(Idle) → 잔여 '녹음 중' 행 있으면 healStaleRecordings() 가 정리

[앱 실행 / 부팅 시에만]  ScheduleManager.catchUpIfMidClass()
   → 지금이 수업 중(종료 전)이고 녹음이 없으면 그때만 시작
```

## 6. 설계상 알아둘 점

- **한 번에 하나만 녹음합니다.** 이미 녹음 중일 때 다른 수업 알람이 울리면 새 요청은 무시됩니다
  (수업이 겹치게 등록된 경우).
- **저장소 접근** — Android 10+ 는 MediaStore(Scoped Storage), 9 이하는 파일 API 를 씁니다.
  그래서 `WRITE_EXTERNAL_STORAGE` 는 `maxSdkVersion="28"` 로 제한했습니다.
- **백그라운드 포그라운드 서비스 시작** — Android 14+ 는 백그라운드 FGS 시작을 막지만, 정확
  알람으로 깨어난 앱은 예외로 허용됩니다. `USE_EXACT_ALARM` 을 선언한 이유입니다.
  (FGS 가 *시작*되는 것과, 그 FGS 가 *마이크를 쓸 수 있는지*는 별개의 제한입니다 — 아래 참고.)
- **녹음 마무리(파일 확정 + DB 갱신)는 서비스가 아니라 앱 스코프 + `NonCancellable` 에서** 실행합니다.
  서비스가 도중에 파괴돼도 마무리가 끝까지 진행되어, "홈 탭은 종료인데 목록은 '녹음 중'이고
  재생 불가" 상태가 남지 않습니다. 여기에 더해 ① 녹음 종료 신호가 올 때마다, ② 앱 시작 시,
  ③ 재생 실패 시 — 세 지점에서 `healStaleRecordings()` 로 pending 파일을 확정하고 길이·용량을
  다시 읽어 채웁니다. 모두 idempotent 이고 `DatabaseTest` 가 검증합니다.
- **비정상 종료 대비** — 서비스는 `START_NOT_STICKY` 라서 OS 가 죽여도 좀비로 되살아나지 않고,
  놓친 녹음은 앱 실행 시 따라잡기 + 위의 heal 로 복구됩니다.
- **무음 녹음 방지 (가장 중요)** — 마이크 while-in-use 권한은 `startForeground()` 가 불리는
  **그 순간**의 앱 상태로 고정된다. 그래서 `RecordingService` 는 `startForeground()` 를
  **인스턴스당 정확히 한 번만** 부른다. 두 번 부르면 그때의 앱 상태로 재평가되어 애써 잡은
  권한을 잃는다(알림 갱신은 `notify()` 로만 한다).
  대기 모드는 앱이 화면에 있을 때 그 한 번을 미리 써 두는 장치다. 그 위에 ① 8초 이상 진폭이
  0 이면 경고 알림 ② 최대 진폭을 DB 에 남겨 목록 표시 ③ `SYSTEM_ALERT_WINDOW` 보조 안내를 둔다.
- **재녹음 버그 대비** — 종료 알람이 트리거하는 재설정은 알람만 다시 걸고, 놓친 녹음 따라잡기는
  앱 실행/부팅 때만 하며 그때도 `sessionInProgress`(종료 시각 지난 수업 제외) 를 씁니다.
  이 규칙들은 `CourseMatchingTest` 의 회귀 테스트로 고정돼 있습니다.
- **DB 스키마 변경** — v1→v2 는 `MIGRATION_1_2` 로 기존 시간표를 보존합니다
  (`groupId` 백필 + `term`/`schedule_exceptions` 테이블 추가). `MigrationTest` 가 검증합니다.
